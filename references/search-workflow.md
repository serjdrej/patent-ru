# Поиск: интейк, под-сценарии, ранжирование, вердикт

Загружайте этот файл, когда: нужно спланировать поиск целиком — выбрать под-сценарий, провести принудительный интейк, вести журнал поиска, распределить роли между `search-rospatent.md` и `search-international.md`, и вынести вердикт.

Методика интейка перенесена (с адаптацией под РФ) из донора `upstream/research-patent/skills/patent` — она дисциплинирует и задаёт стратегию; DOCX-конвейер и англоязычные шаблоны донора не перенесены (см. `search-international.md`).

## 1. Принудительный интейк — один вопрос за раз

1. **Описание изобретения** (2–3 предложения: что делает, что нового). Расплывчатый ответ («ИИ для стройки», «улучшенное устройство») — отклонить, переспросить один раз: «что оно делает такого, чего не делают существующие решения?».
2. **Под-сценарий** — заявитель обязан выбрать один:
   - **novelty** — достаточно ли ново для подачи;
   - **FTO** (freedom-to-operate) — не нарушит ли выпуск чужой патент;
   - **landscape** — кто ещё работает в этой области;
   - **diligence** — действительно ли владеет заявленным объектом (due diligence по сделке);
   - **litigation** — найти основание для оспаривания конкретного патента.
   Отказ выбрать один пункт («все сразу») — переспросить про приоритетную цель; остальные можно догнать отдельными поисками.
3. **Юрисдикции** — только для FTO/landscape/diligence. Для novelty и litigation не спрашивать: приоритет портируем, а юрисдикция litigation задана целевым патентом.
4. **Известный аналог** — если заявитель уже видел близкий патент, искать смежное с ним; «нет» — тоже ответ, подтвердить и продолжить.
5. **Уровень риска** — strict (одно близкое совпадение = отказ от пути) или signal-gathering (нужна общая картина). Не спрашивать для landscape — там всегда signal-gathering.

**Стоп-условие:** после закрытия интейка не переоткрывать его.

## 2. Каналы по под-сценарию

| Под-сценарий | Основной канал | Датная дисциплина |
|---|---|---|
| novelty | `search-rospatent.md`, узкие запросы по терминологии изобретения | приоритет заявки vs предполагаемая дата подачи |
| FTO | `search-rospatent.md` + `search-international.md`, только действующие патенты, фильтр по юрисдикции | дата выдачи + статус (действует/прекращён) |
| landscape | оба канала, широкие запросы, класс МПК/CPC → топ-10 заявителей | дата публикации |
| diligence | поиск по правообладателю и его аффилированным лицам | дата выдачи + дата переуступки |
| litigation | целевой патент → его дата приоритета → поиск искусства до этой даты | дата приоритета целевого патента |

## 3. Обязательные правила извлечения

- Для каждого ближайшего аналога — извлечь **независимый п.1 формулы дословно** через `GET /docs/<id>` (`search-rospatent.md`, раздел 3). Вердикт без текста формулы не выдавать.
- После первичной выдачи — один class-restricted запрос по МПК/CPC топ-5 хитов.
- Различать даты подачи / приоритета / публикации / выдачи и явно указывать, какая из них юридически значима для выбранного под-сценария (таблица раздела 2).
- `similar_search` — только как генератор идей, никогда как ранжированный список ближайшего искусства (жёсткое правило `search-rospatent.md`, раздел 4).

## 4. Журнал поиска

Вести таблицу: № / запрос / источник / получено документов / статус (принят/отказ). В конце — три-счёт (отправлено / получено / процитировано) и перечень отказов источников с причиной.

## 5. Вердикт

Формат зависит от под-сценария: NOVEL / POTENTIALLY NOVEL / NOT NOVEL (novelty); CLEAR / FLAGGED / HIGH RISK по юрисдикции (FTO); карта заявителей (landscape); список красных флагов портфеля (diligence); ранжированный список кандидатов на аннулирование (litigation).

**Обязательная правовая оговорка в каждом вердикте:** результат — поисковый сигнал, а не правовая позиция; решение о подаче, лицензировании или судебной стратегии — за патентным поверенным.
