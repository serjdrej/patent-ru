# Текст: аудит соответствия № 107 и контроль новой материи

Загружайте этот файл, когда: нужно проверить готовый или правленый текст заявки на соответствие Требованиям приказа № 107 и/или на новую материю — без написания текста заново. Не загружайте вместе с `draft-application.md`, `draft-office-action.md` или `draft-divisional.md` — это отдельная, «дешёвая» проверочная задача, обычно выполняемая после того, как текст уже составлен одним из draft-* модулей.

## 1. Машинные проверки — выполнять в этом порядке

### 1.1. Новая материя (п.2 ст.1378 ГК РФ)

```bash
python scripts/novelty_check.py ngram ПРАВЛЕНЫЙ_ТЕКСТ.md --source ИСХОДНИК_1.md --source ИСХОДНИК_2.md
```

5-словные совпадения правленого текста с первоисточниками; участки вне источников короче `--min-run` (по умолчанию 15 слов) — почти всегда швы между переставленными предложениями, не разбирать поимённо. Более длинные участки — разобрать каждый: свести к служебному заголовку/связке (безвредно) либо признать нарушением и убрать.

### 1.2. Неопределённые обозначения

```bash
python scripts/novelty_check.py symbols ПРАВЛЕНЫЙ_ТЕКСТ.md --source ИСХОДНИК.md
```

Для каждого обозначения без определения: если определение есть в первоисточнике — вернуть его (это не новая материя, позиционные номера и обозначения признаками не являются); если не определено и в первоисточнике — унаследованный дефект, зафиксировать и решить с поверенным, не восполнять произвольно новой формулировкой.

**Известный источник шума:** английские слова из списка литературы. Стоплист `STOP` в скрипте расширяемый — пополнять по факту ложных срабатываний, не менять эвристику соседства без проверки на живом тексте.

### 1.3. Ссылочная целостность формулы

```bash
python scripts/claims_integrity.py check ФОРМУЛА.md
```

Ловит: висящие ссылки, ссылки вперёд, независимый пункт со ссылкой на зависимый (в РФ-практике — самостоятельное основание для возражения экспертизы, см. `draft-claims.md`), повторы и разрывы нумерации.

## 2. Ручной чек-лист по Требованиям № 107

| № | Проверка | Норма |
|---|---|---|
| 1 | Описание содержит индекс МПК и все пять обязательных разделов с предписанными заголовками (область техники / уровень техники / раскрытие сущности / краткое описание чертежей / осуществление изобретения) | п.33 Требований |
| 2 | Описание не заменено отсылкой к описанию ранее поданной заявки | п.35 Требований |
| 3 | Раскрытие сущности и осуществление изобретения — с полнотой, достаточной для осуществления специалистом | пп.42–44 Требований, подп.2 п.2 ст.1375 ГК РФ |
| 4 | Материал частей, сборочные операции, интервалы параметров приведены там, где признак этого требует | п.44 пп.1 Требований |
| 5 | Есть пример осуществления и объективные (количественные) данные там, где заявлен технический результат | пп.52–53 Требований |
| 6 | Реферат — до ≈1000 знаков, объём рекомендуемый, а не предельный; при превышении — повод для замечания, не автоотказ | п.80 Требований |
| 7 | Единство изобретения — заявленная группа укладывается в одно из допустимых сочетаний п.63/п.64 либо мотивированно обосновывается через «в частности» (перечень иллюстративный) | пп.63–65 Требований |
| 8 | Прототип выбран ближайшим по совпадению признаков ограничительной части, а не просто похожим по теме | п.41 Требований |
| 9 | Первоначальная заявка не указана прототипом при подготовке выделенной заявки | п.103 Правил |
| 10 | Требования к чертежам — из раздела V, пп.70–76 Требований № 107 **и только из них** | **ГОСТ ЕСКД в периметр скилла не входит — не пересказывать и не цитировать** (решение раздела 8 брифа проекта) |

Полные формулировки/цитаты и статус проверки — в `norms-registry.md`.

## 3. Формат отчёта аудита

Таблица по каждому пункту раздела 2: ✅ соответствует / ⚠️ требует решения (с описанием) / ❌ не соответствует, плюс отдельный блок с выводом машинных проверок раздела 1 (три-счёт участков новой материи, список неопределённых обозначений, список проблем ссылочной целостности). Ни один пункт не остаётся без ответа — либо отмечен как выполненный, либо помечен видимым плейсхолдером `⟦ЗАПОЛНИТЬ: …⟧`.

## 4. Регрессионные примеры (для проверки самого скилла)

На живых данных дела № ⟦НОМЕР ЗАЯВКИ⟧ (формула из 41 пункта):
- `claims_integrity.py check` даёт ровно 5 независимых пунктов: 1, 16, 27, 32, 37;
- `claims_integrity.py renum --drop 32-36` даёт 36 пунктов подряд, без висящих ссылок;
- `novelty_check.py symbols` на паре «первоначальное описание ↔ выделенное описание» помечает `Lbase_offset`, `ΔZphoto`, `Dmeas` как внесённые сборкой (определение есть в первоисточнике — вернуть), а `Lant_offset`, `Lphoto_offset`, `Zant` — как унаследованно неопределённые.

Эти три результата — регрессионный тест самого скилла: любая правка скриптов должна их сохранять.
