# Текст: заявка с нуля (для будущих заявок)

Загружайте этот файл, когда: нужно составить новую заявку на изобретение с нуля — описание, формулу, реферат, выбор прототипа и индекса МПК. Не загружайте вместе с `draft-divisional.md` — выделенная заявка не пишется с нуля, она вербатимно собирается из первоначальных документов (см. там же).

## 1. Состав заявки

Заявление (по форме ФИПС) + описание + формула изобретения + реферат + чертежи (если признаки формулы требуют графического пояснения). Формулу — собирать по `draft-claims.md`, чертежи — по разделу 5 ниже.

## 2. Структура описания — п.33 Требований

Обязательны индекс МПК и пять разделов с предписанными заголовками:

1. Область техники, к которой относится изобретение
2. Уровень техники
3. Раскрытие сущности изобретения
4. Краткое описание чертежей (если чертежи есть)
5. Осуществление изобретения

Замена описания отсылкой к описанию ранее поданной заявки не допускается (п.35 Требований).

## 3. Прототип — выбирать ближайший, а не удобный

**Правило п.41 Требований:** прототип выбирается из предшествующего уровня техники, среди аналогов **совпадающего назначения** — по максимальному совпадению признаков с ограничительной частью будущего п.1 формулы, а не по формальной тематической близости.

**Ошибка, зафиксированная на живом деле:** прототип был выбран слишком далёким (аналог 1977 года), тогда как поиск нашёл более поздний документ, совпадающий с ограничительной частью почти полностью. Дальний прототип отдаёт экспертизе право подставить свой и переформулировать отличительную часть — то есть невыгоден заявителю. Перед фиксацией прототипа — сверить его признаки построчно с ограничительной частью п.1, а не полагаться на тематическое сходство.

Работайте по найденным в `search-rospatent.md` / `search-international.md` аналогам: для каждого кандидата в прототип выписать, какие признаки ограничительной части совпадают дословно, и выбрать максимум.

## 4. Раскрытие сущности и осуществление

Раскрытие — с полнотой, достаточной для осуществления специалистом (пп.42–44 Требований, подп.2 п.2 ст.1375 ГК РФ): материал частей, сборочные операции, интервалы параметров — там, где признак этого требует (п.44 пп.1); пример осуществления и объективные (количественные) данные — там, где заявлен технический результат (пп.52–53). Технический результат для каждого независимого пункта формулировать отдельно и явно указывать причинно-следственную связь с отличительными признаками — расплывчатая формулировка технического результата не защищает от последующей необходимости его конкретизировать, а конкретизация после подачи невозможна без риска новой материи (п.2 ст.1378 ГК РФ, см. `audit-compliance.md`).

## 5. Чертежи — только раздел V (пп.70–76) Требований № 107

**ГОСТ ЕСКД в периметр этого скилла не входит** (решение заказчика, зафиксированное при разработке скилла). Требования к чертежам, графическим материалам и трёхмерной модели изобретения в электронной форме — раздел V Требований, «Требования к чертежам, трехмерной модели изобретения в электронной форме, поясняющим сущность изобретения», пп.70–76 (дословные выдержки и статус проверки — `norms-registry.md`). Коротко: чертежи не должны противоречить описанию (п.70); линии чёрные, чёткие, одинаковой толщины, буквы/цифры не менее 3,2 мм (п.71); нумерация фигур сквозная в порядке упоминания в описании (п.71); предпочтительны ортогональные проекции, элементы — арабскими цифрами по мере упоминания в описании, надписи на чертеже не допускаются кроме служебных слов (п.72); трёхмерная модель — форматы STEP/U3D/PRC/OBJ/STL, до 50 МБ (п.76). ГОСТы ЕСКД не пересказываются и не цитируются здесь. Если по конкретному делу нужно оформление по ЕСКД — это задача вне периметра этого скилла, решать отдельно.

## 6. Реферат

До ≈1000 знаков — рекомендуемый, не предельный объём (п.80 Требований; статус проверки нормы — `norms-registry.md`). Структура: назначение изобретения → состав/конструкция кратко → технический результат последним предложением. При необходимости сокращения — сокращать со второго предложения, не трогая первое (назначение) и последнее (технический результат).

## 7. Индекс МПК

Определять через API Роспатента:

```bash
python scripts/rospatent.py datasets   # если нужно свериться со списком массивов/классификаторов
```

а также `POST /classification/ipc/search/` и `/classification/ipc/code/` (см. `search-rospatent.md`, раздел 6) — эти два метода в `rospatent.py` пока не реализованы, дорабатывать при необходимости. Не подставлять индекс МПК по аналогии с похожим устройством без проверки классификатором — разные подразделения ФИПС ведут разные классы, и неверный индекс перенаправляет дело к другому эксперту без наследования уже достигнутого понимания.

## 8. Единство изобретения при составлении группы пунктов

Если заявка сразу формулируется как группа изобретений (способ + устройство, устройство + вариант) — сверить с допустимыми сочетаниями п.63–64 Требований на этапе составления, не после подачи. См. `draft-claims.md`, раздел 5.

## 9. Жёсткие правила

- Не выдумывать нормируемые значения (интервалы параметров, числовые характеристики технического результата) — только из протоколов испытаний/расчётов заявителя. Нет данных — видимый плейсхолдер `⟦ЗАПОЛНИТЬ: что именно, откуда взять⟧`, а не правдоподобное число.
- Каждый признак формулы должен иметь опору в описании до подачи, не после (см. `draft-claims.md`, раздел 6).
- Один термин на одно понятие по всему комплекту документов.
