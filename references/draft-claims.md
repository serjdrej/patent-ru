# Текст: формула изобретения (составление и редактура)

Загружайте этот файл, когда: нужно составить, отредактировать, разбить на пункты или перенумеровать формулу изобретения. Разделяемый модуль — подключается из `draft-office-action.md`, `draft-divisional.md` и `draft-application.md`; самодостаточен, не ссылается на соседние модули за контекстом.

## 1. Структура пункта

Каждый пункт формулы (кроме независимого п.1, если он ограничительной части не имеет) делится на:
- **ограничительную часть** — признаки, совпадающие с прототипом, до слов «отличающийся тем, что»;
- **отличительную часть** — признаки, отличающие изобретение от прототипа, после этих слов.

## 2. Независимый vs зависимый пункт — правило определения

**Зависимость определяется не наличием ссылки на другой пункт.** Независимый пункт вправе ссылаться на другой пункт, обозначая назначение или целое («Гибридная система…, предназначенная для осуществления способа по п.1, содержащая…»). Признак зависимости — ссылка, за которой **сразу** идёт слово «отличающийся» («Опорный узел системы по п. 16, включающий корпус, … **отличающийся** тем, что…»).

Регулярное выражение в `scripts/claims_integrity.py` учитывает markdown-выделение (`**отличающийся**`) между ссылкой и словом — без этого допущения проверка не срабатывает на форматированном тексте.

## 3. Жёсткое правило ФИПС: независимый пункт не может ссылаться на зависимый

Позиция экспертизы ФИПС, полученная и подтверждённая в живом деле: ссылка независимого пункта на другой пункт **втягивает все его признаки**. Если этот другой пункт — зависимый (то есть сам добавляет признаки к своему базовому пункту), независимый пункт перестаёт быть самостоятельным притязанием и теряет тот объём охраны, ради которого формулировался. Это не редакционная тонкость, а содержательный дефект: переадресовать ссылку независимого пункта с одного пункта на другой (в т.ч. с независимого на зависимый) — не безопасная правка, а способ незаметно сузить или разрушить притязание.

**Проверять всегда:** независимый пункт, ссылающийся на другой пункт, должен ссылаться только на независимый.

## 4. Ссылочная целостность и безопасная перенумерация

```bash
python scripts/claims_integrity.py check ФОРМУЛА.md
python scripts/claims_integrity.py renum ФОРМУЛА.md --drop 32-36           # исключить диапазон
python scripts/claims_integrity.py renum ФОРМУЛА.md --keep 32-36 --rebase 1 --emit   # выделить в новую формулу с 1
```

`check` ловит: висящие ссылки на несуществующий пункт, ссылки вперёд, независимый пункт со ссылкой на зависимый (раздел 3), повторы и разрывы нумерации. Прогонять **до и после** любой правки — это не опциональный шаг.

Формат ссылок, который распознаёт скрипт: «по п. 7», «по пп. 1–3», «по п. 32 или 33», «по любому из пп. 1–5». Формат пункта: строка вида `12. Текст пункта…`.

## 5. Единство изобретения и допустимые сочетания

Заявленная группа изобретений должна укладываться в допустимые сочетания п.63–64 Требований, либо соответствовать общему условию п.2 Требований — техническая взаимосвязь, выраженная одним или несколькими одинаковыми либо соответствующими особыми техническими признаками. Перечень сочетаний в п.64 сформулирован со словами «**в частности**» — он иллюстративный, а не исчерпывающий; несовпадение с буквой примера не опровергает единство само по себе, если общее условие п.2 выполнено. Полные цитаты и статус проверки каждого пункта — `norms-registry.md`.

## 6. Разметка опор в описании

Перед подачей — для каждого пункта формулы явно выписать, каким абзацем/абзацами описания раскрыт каждый его признак («опора»). Пункт без опоры в описании — либо описание нужно доработать (только по уже раскрытым признакам, без новой материи — см. `audit-compliance.md`), либо признак из формулы убрать.

## 7. Жёсткие правила

- Не переносить признаки прототипа в отличительную часть и наоборот — искажает суть возражения экспертизе.
- Не выдумывать зависимость/независимость «на глаз» — только по правилу раздела 2.
- Любая перенумерация — с последующим `check`, без исключений.
- Правки формулы, меняющие объём охраны (не только номера), — решение патентного поверенного, не собственное решение агента; отмечать явным плейсхолдером `⟦РЕШЕНИЕ ПОВЕРЕННОГО: …⟧`.
