# Текст: выделенная заявка (ст.1381 ГК РФ)

Загружайте этот файл, когда: нужно собрать комплект выделенной заявки из пунктов формулы/абзацев описания, отсечённых от первоначальной заявки. Не загружайте вместе с `draft-application.md` — сборка выделенной заявки не пишется с нуля, а вербатимно извлекается из первоначальных документов.

## 1. Правовая основа

- Приоритет выделенной заявки — по дате подачи первоначальной заявки (или по более раннему приоритету первоначальной, если он есть), при условии что первоначальная **не отозвана и не признана отозванной**, и выделенная подана **до одного из двух предельных моментов — какой наступит по факту делопроизводства** (п.4 ст.1381 ГК РФ, дословно — `norms-registry.md`): (а) если по первоначальной заявке **отказано** в выдаче патента — до того, как исчерпана возможность подать возражение на решение об отказе; (б) если по первоначальной заявке **принято решение о выдаче** — до даты государственной регистрации изобретения. Это два разных сценария, не один — определить, по какому из них движется первоначальная заявка, прежде чем считать срок.
- Первоначальная заявка **не входит в уровень техники** для выделенной: не выполнены условия «более ранний приоритет» и «поданная другим лицом» (абз. 3–4 п.2 ст.1350 ГК РФ) — риска самопорочения новизны нет.
- Выделенный патент **не является зависимым** от основного: ст.1358.1 ГК РФ требует более раннего приоритета у другого патента, а здесь приоритеты совпадают.
- Срок действия выделенного патента исчисляется от даты подачи **первоначальной** заявки (п.1 ст.1363 ГК РФ) — оба патента истекают в одну дату.

**Единственная необратимая точка процесса** — предельный момент подачи, см. выше (регистрация изобретения при выдаче патента по первоначальной заявке, либо исчерпание права на возражение при отказе). Между решением о выдаче и регистрацией проходит немного времени, зависящего от скорости уплаты пошлины за регистрацию. Пропуск означает безвозвратную утрату приоритета.

## 2. Прототип — только не первоначальная заявка

**П.103 Правил (дословно, см. `norms-registry.md`):** «признаки, упомянутые на дату подачи заявки в описании изобретения лишь в отношении уровня техники, в том числе и ближайшего аналога изобретения, не относятся к признакам заявленного изобретения». Упоминание выделяемого объекта в разделе «Уровень техники» первоначальной заявки юридически вычеркнуло бы его признаки из раскрытия и лишило бы формулу основания. Прототип выбирается заново, из независимого уровня техники, среди аналогов совпадающего назначения (п.41 Требований) — см. `draft-application.md`, раздел «Прототип».

## 3. Вербатимная сборка описания — единственный безопасный метод

Любой признак, отсутствовавший в первоначальных документах, меняет заявку по существу (п.2 ст.1378 ГК РФ). Поэтому описание выделенной заявки **не пишется заново** — оно собирается вербатимной выборкой абзацев первоначального описания, относящихся к выделяемому объекту, плюс минимально необходимая переориентация заголовков и служебных связок.

**Порядок:**
1. Определить, какие абзацы первоначального описания раскрывают признаки выделяемых пунктов формулы — для каждого пункта отдельно (таблица «пункт → опора»).
2. Собрать пять обязательных разделов по п.33 Требований (индекс МПК; область техники; уровень техники; раскрытие сущности; краткое описание чертежей; осуществление изобретения) из этих абзацев, без добавления нового текста сверх заголовков и служебных связок.
3. **Проверить машинно, что не внесено нового:**
   ```bash
   python scripts/novelty_check.py ngram ВЫДЕЛЕННОЕ.md --source ПЕРВОНАЧАЛЬНОЕ_описание.md --source ПЕРВОНАЧАЛЬНАЯ_формула.md
   ```
   Короткие участки (< 15 слов, порог `--min-run`) — это, как правило, безобидные швы между переставленными предложениями. Длинные участки — разобрать поимённо: каждый либо сводится к служебному заголовку/связке, либо является нарушением и должен быть удалён.
4. **Проверить, что исключение «чужих» абзацев не оторвало определения обозначений**, которые остались в тексте:
   ```bash
   python scripts/novelty_check.py symbols ВЫДЕЛЕННОЕ.md --source ПЕРВОНАЧАЛЬНОЕ_описание.md
   ```
   Если обозначение без определения, но определение есть в первоисточнике — **вернуть его**, это не новая материя (см. правило ниже). Если не определено и в первоисточнике — унаследованный дефект, решать с поверенным, не восполнять произвольно.

**Ключевое правило (легко перепутать в переписке):** обозначение, унаследованно неопределённое в первоначальном описании, — это не то же самое, что обозначение, осиротевшее из-за сборки. Контрольный прогон `symbols` по паре «первоначальное ↔ выделенное» обязателен именно для того, чтобы не приписать сборке чужой дефект.

## 4. Формула выделенной заявки

Перенумеровать отсечённые пункты в самостоятельную формулу, начиная с 1:

```bash
python scripts/claims_integrity.py renum ФОРМУЛА_первоначальная.md --keep 32-36 --rebase 1 --emit
```

Проверить результат `check`-режимом: 0 висящих ссылок, независимый пункт не ссылается на зависимый. Вводная часть первого (независимого) пункта, ранее ссылавшаяся на пункт из основной заявки («…по п. 16, …»), требует редакционного решения: раскрыть ссылку полным наименованием объекта либо исключить отсылку целиком — это влияет на объём охраны, **решение за патентным поверенным**, не подставлять вариант по умолчанию.

## 5. Чертежи

Подавать чертежи **тем же комплектом, каким они шли в первоначальной заявке**, без перенумерации, если сохранённые абзацы описания ссылаются на них. Изъятие отдельных фигур допустимо только если ни один сохранённый абзац на них не ссылается — проверять по факту, не по предположению.

## 6. Реферат

До ≈1000 знаков — **рекомендуемый**, не предельный объём (п.80 Требований, ✅ сверено дословно — см. `norms-registry.md`). При превышении сокращать со второго предложения, не трогая формулировку назначения (первое предложение) и технического результата (последнее).

## 7. Пошлины

Действия выделенной заявки облагаются как для новой заявки: регистрация + формальная экспертиза (1.1), решение по экспертизе по существу (1.8, зависит от числа независимых пунктов), регистрация/публикация/поддержание (1.17). Льгота единственному автору (п.15 Положения № 941) заявляется **отдельным ходатайством к каждой пошлине**, задним числом не возвращается. **Суммы и точный процент здесь не приводятся** — они меняются постановлениями Правительства; перед расчётом открыть текущую таблицу пошлин по ссылке из `norms-registry.md` (раздел 4) и взять актуальные ставки оттуда.

## 8. Чек-лист перед подачей

- [ ] В заявлении — «**выделенная** заявка» (не «отдельная зависимая»), номер и дата первоначальной, ссылка на п.4 ст.1381 ГК РФ
- [ ] Первоначальная заявка не отозвана; предельный момент по п.4 ст.1381 ГК РФ (регистрация при выдаче патента **либо** исчерпание права на возражение при отказе — раздел 1) ещё не наступил
- [ ] Подача — одновременно с ответом по разделу выбора группы или сразу после; не ждать решения по основной заявке
- [ ] `novelty_check.py ngram` и `symbols` прогнаны на итоговом тексте, длинные участки разобраны поимённо
- [ ] `claims_integrity.py check` на итоговой формуле — 0 проблем
- [ ] Индекс МПК проставлен и, по возможности, согласован с патентным поверенным (смена класса — другое подразделение и другой эксперт ФИПС, без наследования понимания по основной заявке)
- [ ] Реферат уложен в объём
- [ ] Ходатайство о льготе приложено к каждой пошлине отдельно
- [ ] ⟦ЗАПОЛНИТЬ: конкретные позиционные обозначения/описки, унаследованные из первоначального описания⟧ — решены или сознательно оставлены с пометкой
