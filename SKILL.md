# Патентный поиск и делопроизводство РФ (Роспатент / ФИПС)

Два независимых ветвления: **поиск** аналогов и **написание/редактура** документов заявки по Требованиям приказа Минэкономразвития № 107. Загружайте ровно один `references/*.md` под конкретную задачу — не всю ветвь и не обе ветви разом.

## Стыки — где допустимо два reference за раз

- «не порочит ли найденный аналог нашу формулу» → `search-*.md` + `draft-claims.md`
- «ответ на уведомление требует правки формулы» → `draft-office-action.md` + `draft-claims.md`
- «выделенная заявка требует собственной формулы» → `draft-divisional.md` + `draft-claims.md`

Во всех остальных случаях — один файл. Если задача не укладывается ни в одну строку таблицы, читайте только заголовок «Загружайте этот файл, когда: …» нужных кандидатов, а не их целиком.

## Пример дисциплины ключа

Ключ хранится централизованно на компьютере — не в дереве скилла и не привязан к тому, откуда и сколько раз скилл установлен (библиотека навыков, отдельная папка, другая копия репозитория). Один и тот же `rospatent.py` на Windows и macOS — никаких PowerShell/bash-обёрток: если `ROSPATENT_API_KEY` не задана в окружении, скрипт сам достаёт ключ из защищённого хранилища ОС (`scripts/keystore.py`: DPAPI на Windows, Keychain на macOS).

```bash
python scripts/rospatent.py set-key      # разово на компьютер, ввод скрытый
python scripts/rospatent.py search '(веха OR "измерительная штанга") AND инерциальн*'
```

## Жёсткие правила

- **Дисциплина ключа.** `ROSPATENT_API_KEY` читается только из переменной окружения или из хранилища ОС через `keystore.py` — никогда не вписывается в команду и не печатается, не логируется, не сохраняется в JSON/отчётах/коде. Перед первым вызовом в сессии проверить, настроен ли ключ (`python scripts/rospatent.py datasets` вернёт понятную ошибку, если нет). Если не настроен — **не запрашивать ключ в переписке**: показать пользователю ровно одну команду для его собственного терминала — `python scripts/rospatent.py set-key` — и подождать, пока он её выполнит сам. Повторять не нужно: настройка одноразовая на компьютер, действует на любую установку скилла на этом компьютере.
- **Правовая оговорка.** Результат — поисковый сигнал или черновик текста, а не правовая позиция. Решение по стратегии, редакции формулы и индексу МПК — за патентным поверенным.
- **Не выдумывать нормы.** Реквизиты, цитаты и статус проверки норм — только из `references/norms-registry.md`. Перед подачей любого документа в ФИПС проверить применённые пункты по действующей редакции — реестр является рабочей опорой, а не источником истины.
- **ГОСТ вне периметра.** ЕСКД не пересказывается и не цитируется. Требования к чертежам берутся только из раздела V (пп.70–76) Требований № 107.
- **Формула:** независимый пункт не может ссылаться на зависимый (позиция экспертизы ФИПС) — см. `draft-claims.md`.
- **`similar_search` Роспатента** — не доказательство отсутствия аналогов, см. `search-rospatent.md`.
- **Плейсхолдеры** — видимые и одноформатные: `⟦ЗАПОЛНИТЬ: что именно, откуда взять⟧`.
- **Пробел в реестре — см. «Протокол пробела в базе» ниже, не заполнять его
  по памяти.**

## Как править этот файл

Новая оговорка пишется туда, где будет читатель в момент ошибки. Носители по
убыванию предпочтения: **(1)** поле в выводе скрипта — оно приходит с данными
и закрывается тестом; **(2)** файл в `references/`, который маршрут обязывает
открыть; **(3)** этот файл. Выбор (3) требует назвать, почему (1) и (2) не
подходят: поле не несёт того, что нужно **до** вызова — агент, не вызвавший
скрипт, поля не видел. И оговорка называет условие своего удаления, иначе они
только накапливаются: `--article` ушёл отсюда, девять строк в пять, потому что
назвал, что его отменит, и это случилось (`git show --stat 928e784`). Этот файл
вырос с 56 строк до 148 за одиннадцать дней при заявленном в README бюджете
роутера ≤100, и 87 из них занимал один раздел, пришедший одним коммитом, —
таким он был к моменту появления этого правила (`git log --format='%h %cs %s'
-- SKILL.md`, затем `git show <hash>:SKILL.md | wc -l`).

## Протокол пробела в базе

*Ступень (3) по правилу выше — намеренно: этот протокол читают, когда ни один
маршрут не подошёл, а файл в `references/` не может нести то, что решает, какой
`references/` открывать и что ни один не подходит. Размер раздела этим не
оправдан: разметка его случаев на адресуемые части остаётся открытой, см.
`docs/pending-work.md`.*

Триггер: вопрос не ложится ни в одну строку таблицы маршрутизации выше, или
ложится в одну из ветвей, но нужной нормы нет в `norms-registry.md`. Правило
«не выдумывать нормы» распространяется и сюда — пробел не повод отвечать по
памяти так, будто это проверенная норма. Различать два случая:

1. **Это ещё один из четырёх актов реестра (ГК РФ ч.4, приказ №107, Регламент
   №163, Постановление №941), просто нужный пункт не занесён в таблицу, и
   вопрос про текст/действие самого акта** — не про то, как его применяют
   ФИПС или суды (это случай 2, даже если назван конкретный пункт). У этого
   скилла нет скрипта для текста законодательства — `rospatent.py` ищет
   патентные документы, не нормы. Живая перепроверка здесь — маршрут раздела
   5 `norms-registry.md` (rospatent.gov.ru/ru/docs → категория по разрезу →
   найти акт по номеру и дате). Агент обязан реально открыть эту страницу
   (WebFetch или браузер), а не только упомянуть маршрут пользователю — тот
   же принцип, что «Живая перепроверка» у `legal-ru`, но здесь маршрут не
   обкатан скриптом так, как `pravo_lookup.py` обкатан там. **Известная
   проблема, подтверждена 2026-09-14 независимо (WebFetch и отдельно
   `urllib` дают одну и ту же ошибку): WebFetch не может проверить цепочку
   сертификата rospatent.gov.ru — типичная ошибка `certificate verify
   failed` / `unable to verify the first certificate`, это не таймаут и не
   недоступность сайта.** Если WebFetch отказал именно так — не пытаться
   отключить проверку сертификата (запрещено, это ослабление TLS), а
   использовать браузерный инструмент (`Claude_Browser`/аналог) — он у
   агентов, работающих локально, как правило открывает сайт нормально;
   зафиксировать в ответе, каким именно способом получилось открыть
   страницу. Если недоступны оба — сказать об этом честно, а не молчать.
   **Важно:** открытие страницы подтверждает, что акт существует и какая у
   него дата редакции — не подтверждает автоматически конкретную цифру,
   срок или формулировку, если вы не прочитали именно нужный абзац. Пометка
   обязана прямо сказать, какой из двух уровней достигнут: **AD HOC — акт
   подтверждён живым поиском по маршруту раздела 5 `<дата>`, дата редакции
   на странице — ⟦указать⟧**, и затем один из двух вариантов: **содержание
   ниже — дословная выдержка со страницы (если удалось прочитать нужный
   абзац целиком)**, либо **содержание ниже — не дословная выдержка,
   сверить лично перед использованием (если подтверждён только факт/маршрут,
   без чтения нужного абзаца)** — не путать эти два варианта.

   **Для федерального закона или ведомственного приказа маршрут короче, и он
   сразу даёт дословный вариант.** `scripts/ips_lookup.py find --number "107"
   --date 21.02.2023` возвращает `nd`, `text <nd>` — сводный текст акта с
   пометками редакций внутри. Это надёжнее чтения страницы браузером: текст
   приходит скриптом, а не глазами по вёрстке, и редакция названа явно.

   Проверено 2026-09-16: на ГК ч. 4 `--article 1363` отдаёт одну статью
   (4 869 знаков). На акте, который делится на пункты, а не на статьи —
   приказе, постановлении, правилах — флаг неприменим, и скрипт говорит это
   сам: поля `act_uses_articles`, `article_headings_in_act` и команда для
   повтора без флага в ноте. Пустой `--article` нормы не отменяет.

   Браузерный маршрут выше остаётся для того, чего в ИПС нет: регламентов и
   разъяснений ФИПС, практики СИП. Чего ИПС не даёт ни в каком случае — дат
   вступления редакций в силу. Если по ходу
   этого поиска обнаружится ссылка на акт, который не входит в число
   зарегистрированных четырёх (например, отсылочная норма к отдельному
   приказу) — факт его существования можно зафиксировать как случай 1 (акт
   найден), но его содержание уже разбирать по случаю 2 ниже, а не
   пересказывать по памяти только потому, что название нашлось в ходе того
   же поиска. Если тема повторится — предложить пользователю превратить
   находку в постоянную запись реестра.
2. **Не один из этих четырёх актов, или вопрос про практику применения, а не
   про текст нормы** — полезные модели, промышленные образцы, товарные знаки
   (другие объекты ГК РФ ч.4, не изобретения — вне периметра этого скилла,
   даже если структурно похожи на раздел 1 реестра), международная/PCT-
   процедура, патентное право другой страны, оспаривание патента, практика
   Суда по интеллектуальным правам или ФИПС по конкретной норме (номер
   пункта в вопросе сам по себе не делает его случаем 1, если спрашивают не
   про текст, а про то, как его применяют), ГОСТ/ЕСКД (уже вне периметра по
   «Жёстким правилам» выше). Ни `rospatent.py` (ищет патентные документы, не
   нормы), ни маршрут раздела 5 (только эти четыре акта) сюда не приведут.
   Не подменять пробел обучающими данными, даже в осторожной формулировке.
   Сказать пользователю прямо, что вопрос вне периметра скилла, и спросить,
   как продолжать: (a) открытый веб-поиск с явной пометкой «не проверено, не
   первоисточник»; (b) пользователь сам называет акт или дело, которое нужно
   проверить живым поиском; (c) вопрос — к патентному поверенному или
   профильному специалисту по этому объекту ИС/юрисдикции, не к этому
   скиллу.

Не смешивать пометку **AD HOC** со статусом «✅ сверено дословно» или с
обычным парафразом реестра без явного разделения — пользователь должен
видеть, какому утверждению можно доверять как проверенной записи, а какому
нет, и какая часть AD HOC-находки — подтверждённый факт (акт существует), а
какая — непроверенный пересказ содержания.

## Скрипты

| Скрипт | Роль |
|---|---|
| `scripts/rospatent.py` | клиент API Роспатента: `search`/`doc`/`similar`/`datasets`/`ipc`/`set-key`, ретраи, три-счёт |
| `scripts/ips_lookup.py` | Официальная ИПС «Законодательство России»: `find` находит акт и его `nd`, `redactions` перечисляет редакции, `text <nd> --article M` отдаёт **сводный текст статьи** (проверено на ГК РФ ч. 4, `nd=102110716`, ст. 1363). Без ключа. Дат вступления редакций в силу не даёт. |
| `scripts/keystore.py` | хранилище ключа вне дерева скилла: DPAPI (Windows) / Keychain (macOS), без сторонних пакетов; используется `rospatent.py` автоматически |
| `scripts/claims_integrity.py` | ссылочная целостность формулы и безопасная перенумерация (`check` / `renum`) |
| `scripts/novelty_check.py` | новая материя (`ngram`) и неопределённые обозначения (`symbols`) |
| `scripts/google_patents.py` | fallback-поиск через `xhr/query` + дословный текст из PDF, минуя блокируемую `/patent/<ID>` (см. `search-international.md`) |
