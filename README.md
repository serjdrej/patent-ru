# patent-ru

Если вы ведёте патентное дело сами — без штатного патентного поверенного на
подхвате — приходится и искать аналоги по базе Роспатента, и писать документы
заявки по строгой форме приказа Минэкономразвития № 107. Без чёткой методики
ИИ-ассистент обычно либо выдумывает реквизиты нормы, которую не проверял, либо
упускает обязательный пункт формы. Этот Agent Skill для Claude Code даёт
проверенную на живом деле методику поиска по API Роспатента и ведёт через
структуру приказа № 107, не давая спрятать пробел за правдоподобной фразой.

Результат — поисковый сигнал или черновик текста, а не правовая позиция и не
документ, готовый к подаче. Решение по стратегии, редакции формулы и индексу
МПК — за патентным поверенным.

## Что делает

- Ищет аналоги и уровень техники по российскому и советскому патентному фонду
  (RU/SU) через API Поисковой платформы Роспатента —
  [`references/search-rospatent.md`](references/search-rospatent.md).
- Ищет за рубежом (Google Patents/Espacenet/USPTO) или когда доступа к API
  Роспатента нет — [`references/search-international.md`](references/search-international.md).
- Планирует поиск целиком: выбор под-сценария, журнал, вердикт —
  [`references/search-workflow.md`](references/search-workflow.md).
- Готовит ответ на уведомление ФИПС/запрос экспертизы, выделенную заявку
  (ст. 1381 ГК РФ), заявку с нуля и формулу изобретения —
  `references/draft-*.md`.
- Проверяет документы на соответствие Требованиям № 107 и на новую материю —
  [`references/audit-compliance.md`](references/audit-compliance.md).

Триггеры: патентный поиск, поиск аналогов, база Роспатента, формула
изобретения, заявка на изобретение, уведомление ФИПС, нарушение единства
изобретения, выделенная заявка, ответ на запрос экспертизы, реферат,
прототип, новая материя, п.2 ст.1378 ГК РФ.

## Чего НЕ делает

- **Не доказывает отсутствие аналогов.** `similar_search` Роспатента — генератор
  идей для последующих ключевых запросов, а не подтверждение чистоты поиска
  (метрика эмпирически не дискриминирует, см. `search-rospatent.md`).
- **Не выдумывает нормы.** Реквизиты и цитаты статей/пунктов — только из
  [`references/norms-registry.md`](references/norms-registry.md); для
  быстро меняющихся источников (ГК РФ, ставки Положения № 941) там — ссылка и
  инструкция, как проверить актуальную редакцию, а не встроенный текст.
- **ГОСТ/ЕСКД вне периметра.** Требования к чертежам — только из раздела V
  Требований № 107, не из стандартов ЕСКД.
- **Не отвечает по памяти на то, что вне реестра.** Полезные модели,
  промышленные образцы, товарные знаки, международная/PCT-процедура, патентное
  право другой страны, практика ФИПС/СИП — вне периметра. `SKILL.md`, раздел
  «Протокол пробела в базе»: скилл либо ищет живьём по маршруту
  `norms-registry.md` (для ещё одного из четырёх охваченных актов) и помечает
  находку **AD HOC**, либо прямо говорит, что вопрос вне базы, и спрашивает,
  как продолжать — вместо того чтобы выдавать правдоподобный, но непроверенный
  ответ.

## Как установить

**Через маркетплейс, Claude Code:**
```
/plugin marketplace add serjdrej/ru-legal-skills
/plugin install patent-ru@ru-legal-skills
```

**Через маркетплейс, Codex CLI:**
```
codex plugin marketplace add serjdrej/ru-legal-skills
codex plugin add patent-ru@ru-legal-skills
```

Обе команды читают один и тот же `ru-legal-skills/.claude-plugin/marketplace.json`
— проверено вживую на обоих рантаймах.

**Отдельно, без маркетплейса** — склонировать репозиторий в директорию
скиллов Claude Code (`~/.claude/skills/patent-ru` — на других CLI-рантаймах
может отличаться, см. их документацию):
```
git clone https://github.com/serjdrej/patent-ru.git ~/.claude/skills/patent-ru
```

## Как это устроено

Точка входа — [`SKILL.md`](SKILL.md): роутер (≤100 строк), маршрутизирующий задачу на один файл из `references/`. Ветви «поиск» и «написание/редактура» никогда не загружаются вместе.

```
SKILL.md
references/   — 9 модулей: поиск (Роспатент/зарубежные источники/интейк) и текст
                (ответ ФИПС, выделенная заявка, аудит, формула, заявка с нуля,
                реестр применяемых норм)
scripts/      — 5 скриптов, чистый stdlib (кроме pdftotext для google_patents.py):
                rospatent.py, google_patents.py, claims_integrity.py, novelty_check.py,
                keystore.py (хранение ключа вне дерева скилла: DPAPI на Windows,
                Keychain на macOS — см. `python scripts/rospatent.py set-key`)
```

**Статус:** самостоятельный репозиторий, входит в маркетплейс
[`ru-legal-skills`](https://github.com/serjdrej/ru-legal-skills) вместе с
[`legal-ru`](https://github.com/serjdrej/legal-ru) и
[`gost-ed-mashiny`](https://github.com/serjdrej/gost-ed-mashiny) — это и есть
актуальный канал распространения; сторонние копии этого скилла вне репозитория
и маркетплейса не поддерживаются и могут отставать.

**Тестирование:** регрессионные тесты (см. `references/audit-compliance.md`,
раздел 4) прогонялись на реальном деле автора (номер не приводится) и проходят
— эта методика старше остального семейства и не то же самое, что нагрузочное
тестирование RED→GREEN→REFACTOR у `legal-ru`; не путать при отчёте о статусе.
Отдельно, 2026-09-14: «Протокол пробела в базе» (`SKILL.md`) прогнан по
методике RED→GREEN→REFACTOR того же `legal-ru` — baseline-агент без скилла
против агента со скиллом на одинаковых вопросах вне реестра. GREEN-прогон
реально запускал WebFetch/браузер против rospatent.gov.ru и вскрыл два
реальных пробела в формулировке протокола, оба исправлены: неверное
предположение, что живой поиск даёт только метаданные (иногда даёт дословный
текст — пометка теперь различает оба случая), и не описанный сценарий, когда
поиск по случаю 1 сам находит акт вне реестрируемой четвёрки.

**Отложено:** нужен ли этому скиллу отдельный круг проверки цитат перед
выдачей ответа — открытый вопрос с заранее принятым правилом решения и
готовой методикой замера, см. [docs/pending-work.md](docs/pending-work.md).
В соседнем `arbitrazh-ru` такой механизм измерен и отклонён, но нулевой
результат между скиллами не переносится: трафик разный.
